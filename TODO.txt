================================================================================
 AGENT SMITH - TODO & DECOUPAGE DU TRAVAIL
================================================================================
Projet : Framework agentique (Code Agent) resolvant des taches de code de
         facon autonome via une boucle Thought -> Code -> Observation.
Benchmarks : MBPP (simple, a faire en premier) + SWE-bench (Docker, plus dur).
================================================================================


--------------------------------------------------------------------------------
 RESUME DU PROJET
--------------------------------------------------------------------------------
Boucle centrale :
    THOUGHT (le LLM raisonne)
      -> CODE (il ecrit du Python executable)
        -> OBSERVATION (execution dans le sandbox)
          -> repeter jusqu'a final_answer()

Approche "code-based tool calling" : le LLM genere du code Python qui appelle
directement les outils (variables persistantes, boucles, logique conditionnelle).

Composants majeurs :
  1. Orchestrateur / boucle agentique      (100% maison - PAS de langgraph,
                                             smolagents, crewai, autogen...)
  2. Extraction de code                     (Python + XML/JSON/ReAct -> Python)
  3. Sandbox securise                       (stdlib only, PAS de RestrictedPython)
  4. Serveur(s) MCP                         (stdio ET HTTP, outils dynamiques)
  5. Multi-provider LLM                     (free tier, multi-tokens + rotation)
  6. Rapport de benchmark                   (>=5 modeles x >=3 taches SWE-bench)


--------------------------------------------------------------------------------
 CONTRAINTES TECHNIQUES
--------------------------------------------------------------------------------
  [ ] Python 3.10
  [ ] uv comme package manager
  [ ] Architecture clean, code lisible/structure/documente
  [ ] Toutes les erreurs gerees gracieusement (un crash = echec)
  [ ] Cles API via .env / env vars (JAMAIS en dur -> flag securite = 0)
  [ ] Boucle agentique = implementation maison obligatoire
  [ ] Sandbox : stdlib Python uniquement (pas de lib externe de securite)
  [ ] Pydantic models imposes :
        - SandboxConfig
        - MBPPTaskInput
        - SWEBenchTaskInput
        - StepMetrics
        - SolutionOutput


--------------------------------------------------------------------------------
 LIMITES D'EVALUATION (a respecter STRICTEMENT)
--------------------------------------------------------------------------------
  Metrique          | MBPP    | SWE-bench
  ------------------|---------|-----------
  Iterations max    | 10      | 30
  Input tokens      | 6 000   | 300 000
  Output tokens     | 1 500   | 10 000
  Timeout           | 120 s   | 900 s
  Seuil reussite    | 4 / 5   | 2 / 3

  - Tokens cumulatifs sur toutes les iterations d'une tache.
  - Tokens de reasoning comptent aussi -> preferer modele non-reasoning si serre.
  - Aucun retry autorise pendant l'examen.


--------------------------------------------------------------------------------
 AI SAFETY (violation = note de 0)
--------------------------------------------------------------------------------
  L'agent doit resoudre par EXPLORATION LEGITIME. Interdit :
  [ ] Recuperer des solutions depuis PRs / issues / sources externes
  [ ] Utiliser des patches memorises sans exploration reelle
  [ ] Contourner les contraintes du sandbox
  [ ] Acceder a des ressources hors du contexte de la tache
  Les champs system_prompt / llm_output / sandbox_input / sandbox_output sont
  logges pour tracer le raisonnement.


--------------------------------------------------------------------------------
 OUTILS OBLIGATOIRES (exposes via MCP, testes independamment)
--------------------------------------------------------------------------------
  Filesystem :
  [ ] read_file(filepath, start_line, end_line)   -> format type "cat -n"
  [ ] edit_file(filepath, old_str, new_str)       -> remplacement exact
  [ ] list_files(directory, pattern)

  Recherche :
  [ ] search_code(pattern, file_pattern)          -> grep-like, format /path:ligne
  [ ] search_function_or_class_definition_in_code(name)
  [ ] find_references(name, filepath, line)

  Execution :
  [ ] run_tests()                                 -> lance le script d'eval
  [ ] get_patch()                                 -> git diff unifie
  [ ] run_command(command, workdir)               -> stdout, stderr, exit code
